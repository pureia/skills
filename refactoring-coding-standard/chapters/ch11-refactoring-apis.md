# 第11章：重构 API

## Core Idea
API 组让接口言简意赅：查询与修改分离、参数化/去标记化、对象整体传递、参数与查询互转、用工厂与命令替代过时的构造/动词函数形态。

## Frameworks Introduced

### 将查询函数和修改函数分离（Separate Query from Modifier）
- 动机：函数既返回值又改数据——调用者容易忽略副作用；多线程更危险
- 做法：① 复制出查询函数（只读）② 被复制处加个辅助：把副作用兜进修改函数 ③ 原函数改为调查询 ④ 全部调用者调整 ⑤ 测试
- 要点：命名规范看家——`total()` 若是有副作用，名字也会骗人

### 函数参数化（Parameterize Function）
- 动机：两个函数几乎相同只有字面量不同（重复代码）
- 做法：① 写出与新旧两函数匹配的参数化函数（可选：从其中一个改起）② 逐个把调用者切过来 ③ 删旧函数 ④ 测试
- 判断信号：函数体内只有值不同→参数；行为模式不同→不要硬参数化

### 移除标记参数（Remove Flag Argument）
- 动机：参数只用来判断走哪条路径（`isMale ? ... : ...`），调用点语焉不详
- 做法：① 按标记值的语义拆成多个具名函数（或保留具名布尔包装）② 每个调用点改用明确函数名 ③ 测试；也可用两函数体共用私有实现
- 要点：具名函数可比"布尔+参数重载"更自描述，且未来某个分支更独立时更好改

### 保持对象完整（Preserve Whole Object）
- 动机：调用者从对象里拆出一堆字段传参；函数签名又长又依赖于"哪个字段叫什么"
- 做法：① 改签名直接收对象 ② 函数体内读出所需字段 ③ 更新调用者 ④ 测试
- 反向考虑：对象是"裸变量袋"时拆散更清晰（区分"是否是真正聚合的数据"

### 以查询取代参数（Replace Parameter with Query）
- 动机：调用处传入的实参是同一对象上的属性——参数化反而增加"调用者的知识负担"
- 做法：① 找出被调用函数的调用点 ② 函数内部用它可及的查询获得该值 ③ 删参数，测试；若某次调用方没这数据→保留参数重载（"参数是例外"场景）

### 以参数取代查询（Replace Query with Parameter）
- 动机：函数内部直取全局/远端查询，测试与理解都需要"隔离的输入"
- 做法：① 加参数接收值 ② 调用者算出不可分离值传入 ③ 测试
- 收益：与用户交互/环境的耦合从函数体移到调用点

### 移除设值函数（Remove Setting Method）
- 动机：字段只应在构造时设定；暴露 setter 让对象永远可变
- 做法：① 检查 setter 的所有调用点 ② 把"构造后赋值"的调用点改到构造函数/工厂里 ③ 删 setter ④ 测试
- 收益：不可变语义、缩小作用域

### 以工厂函数取代构造函数（Replace Constructor with Factory Function）
- 动机：构造函数在 JS 等语言中必须 `new`，匿名、无法按类型选择子类/返回类型
- 做法：① 建 `createXxx` 工厂函数 ② 函数体内 return new ③ 逐调用点替换 ④ 测试；再提取参数差异为多工厂
- 收益：语义命名的入口（如 `createEmptyDateRange`）、可返回子类型

### 以命令取代函数（Replace Function with Command）
- 动机：函数参数/临时变量太多；想随状态分步执行（execute 模式）；想封装"一个算法的多次调用"
- 做法：① 建类，字段承载上下文 ② 函数体多段拆方法 ③ 顶层方法 `execute()` ④ 构造上下文、调用 execute ⑤ 替换调用点 ⑥ 测试；（常配合拆分为"三步走"的命令）

### 以函数取代命令（Replace Command with Function）
- 动机：命令类只剩一个方法时是过度结构（冗赘元素）；命令要"用完即弃"时也是
- 做法：① 识别命令 ② 把 execute 的上下文参数改为函数参数 ③ 折叠成普通函数 ④ 删类 ⑤ 测试

## Mental Models
- **函数签名的诚实**：能由查询得到的参数不要传；改数据的查询要拆开；标记参数是"隐藏分支"
- **工厂 vs 构造**：学名给出入口，动态返型号是工厂的本质优势
- **命令 vs 函数**：需要"复杂算法的分步控制/复用上下文"→命令；简单调用→函数
- **参数与查询的双向替换**：谁是"输入"，谁依赖环境——测试时反着选

## Worked Example
移除标记参数：`setDimension(name, value)` 与 `width/height` 分支——重构前后：
```javascript
// 前
setDimensions("width", 5); setDimensions("height", 10);
// 后
setWidth(5); setHeight(10);  // 内部共享私有实现
```
- **What it demonstrates**: 布尔/枚举标记参数把"意图"藏进布尔值，删除后调用点自解释

## Key Takeaways
1. 查询与修改分离是底线——"看到红条永远不重构"外的另一条铁律
2. 两个函数只差字面量→参数化；一个参数只用于选路径→移除
3. 传对象 vs 传字段：被传对象是"真正聚合"就保持对象完整
4. 构造后不可变的字段：删 setter；需要按语义选择实现：用工厂
5. 命令是"函数复杂度的收纳盒"：能装起来执行，也要能折叠回去
