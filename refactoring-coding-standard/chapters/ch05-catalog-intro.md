# 第5章：介绍重构名录

## Core Idea
本章介绍重构名录（catalog）的使用方法：每个重构按统一格式记录——名称（含别名）、速写（sketch）、动机、做法（mechanics）、范例——名录是"参考工具"，按需查阅，而非通读的书。

## Frameworks Introduced
- **重构名录记录格式（5 段式）**：
  - **名称（Name）**：构建重构词汇表的关键，列常见别名
  - **速写（Sketch）**：一小段代码展示转变，帮助回忆（第一次接触则读范例）
  - **动机（Motivation）**：为什么做、什么时候不该做
  - **做法（Mechanics）**：分小步的检查清单，要求逐步测试；"小步前进，情况越复杂，步子就要越小"
  - **范例（Examples）**：最小化的教科书式示例；某些简单重构无范例
- **挑选重构的依据**：常用、值得命名、能提升整体技能或对设计质量提升显著；反向重构大多不单列（如封装变量很少反向做）；太小的重构（如移动语句）早年不入名录

## Key Concepts
- **婴儿学步（baby steps）**：实际工作中常用比名录更大的步子，一旦出问题就撤销、改用更小步
- **词汇表价值**：名称可以在团队与工具（IDE 自动重构）中复用为元语言
- **范例的颜色标注**：书中用高亮显示修改过的代码；比例过多时不突出（防止淹没重点）

## Mental Models
- **目录即回忆工具**：知道"该用哪个重构"但记不清步骤时，只看做法；初次使用则做法+范例都读
- **每个重构都有一位反向重构**：选择是否记录取决于"反向是否常用/有趣"

## Anti-patterns
- **把名录当教材通读**：它首先是参考手册；范例是为解释单个重构而简化，不是优秀业务建模
- **抄名录的简单范例到复杂场景**：范例是脚手架，真正使用时需结合上下文做变体

## Worked Example
使用场景：一个多月没做"搬移语句到调用者"，回忆不起细节 → 查阅该条目做法清单：确认调用者、逐个搬移、删除原语句、测试——照单执行，不再凭印象。

## Key Takeaways
1. 重构手册的每一条都遵循同一格式，学会从"速写"定位要查的手法
2. 做法是安全基线：每步骤后测试；"小步前进，情况越复杂，步子越小"
3. 名录只收录最常用/最有价值的手法——不要为"没列出"的重构而困惑
4. 记录格式本身就是一种"知识管理"：名称-速写-动机-做法-范例
