# 第6章：第一组重构

## Core Idea
第一组重构是构建"函数"及其组合的基础手法：提炼/内联函数与变量、改名、封装变量、参数对象化、函数组织成类/变换、拆分阶段。这是最低层级的重构——"形成函数并给函数命名"的精髓。

## Frameworks Introduced

### 提炼函数（Extract Function）
- 动机：看到需要花时间才能看懂的代码段（尤其顶部有注释时），将意图与实现分离
- 做法：① 以"做什么"命名创建新函数（嵌套进源函数以减少作用域问题）② 复制代码 ③ 检查越界变量→作参数传入；被赋值的单变量→改为查询返回；多个被赋值变量→先拆分变量/以查询取代临时变量 ④ 编译 ⑤ 替换调用 ⑥ 测试 ⑦ 搜索重复代码改用新函数
- 失败模式：想不出好名字→也许不该提炼；提炼后发现不合适→内联回去

### 内联函数（Inline Function）
- 动机：函数体与名字一样清晰/函数只被一个调用点使用/已不合适的间接层；与提炼函数互为反向
- 做法：① 确认多态调用不适用 ② 找出所有调用点 ③ 将函数体逐段替换进调用点（一次一个）④ 删除原函数 ⑤ 测试

### 提炼变量（Extract Variable）
- 动机：表达式难理解（如 `if (platform.usesMac && ...)` 的深层条件），或者成为复杂表达式的一部分想复用
- 做法：① 确认要提炼的表达式没有副作用 ② 声明新变量并赋值 ③ 替换原表达式 ④ 测试；重复使用→提炼成函数（更受欢迎）

### 内联变量（Inline Variable）
- 动机：变量名没比表达式表达更多/变量挡住了提炼；与提炼变量互为反向
- 做法：① 确认变量赋值表达式无副作用、被赋值一次 ② 检查是否只被用一次 ③ 替换为表达式 ④ 删除变量 ⑤ 测试

### 改变函数声明（Change Function Declaration）
- 动机：改名（名称久用不贴切）、增删参数、改参数类型（含迁移式 New Function）
- 做法（直接式）：① 声明新签名 ② 改调用者（用 IDE 或逐处）③ 移除旧函数 ④ 测试
- 做法（迁移式，公开接口/难找全调用者）：① 新建目标函数 ② 旧函数套薄壳转发 ③ 逐个迁移调用者 ④ 删旧函数；参数值迁移同理
- 要点：这是最常用的重构之一（神秘命名的主要疗法）

### 封装变量（Encapsulate Variable）
- 动机：全局数据/大范围可变数据危险性高；把访问收口到函数里
- 做法：① 建取值/设值函数 ② 静态检查 ③ 把函数名改为 get/set 形式 ④ 测试 ⑤ 把返回的集合/引用考虑不可变（返回副本）
- 要点：所有改数据的路径都必须经过设值函数——这就是"控制访问"的意义

### 变量改名（Rename Variable）
- 动机：变量的含义随理解加深而变化
- 做法：① 确认作用域不大（函数内小作用域→查找替换即可；大作用域→先封装变量）② 改名所有引用 ③ 测试；配合 IDE 的重命名更安全

### 引入参数对象（Introduce Parameter Object）
- 动机：多个参数总是成对出现（数据泥团）；函数间共享
- 做法：① 新建值对象类 ② 从参数中选出共同项 ③ 修改函数签名 ④ 更新调用者按新对象传参 ⑤ 测试；随后常做搬移函数把行为放入
- 收益：参数列表缩短，出现"调令(可做很多事)的对象"

### 函数组合成类（Combine Functions into Class）
- 动机：一组函数操弄着同一组数据（全局数据/长参数列表场景）
- 做法：① 建类 ② 把数据作为字段搬入 ③ 把函数搬进去（参数改为字段引用）④ 把调用节点改成类实例 ⑤ 测试；可再提炼类（本质是"组合函数-对象"模式）

### 函数组合成变换（Combine Functions into Transform）
- 动机：函数组合式地处理同一份只读数据；与组合成类是两条路径
- 做法：① 建变换函数接收原始数据 ② 逐步把计算逻辑搬进去 ③ 无字段，对每次要结果调用一次 ④ 数据源仍保持原样；测试

### 拆分阶段（Split Phase）
- 动机：一段代码前后处理两件完全不同的事（如先解析再计算；先算再渲染）
- 做法：① 识别阶段边界（顺序性的两组变换）② 把第二阶段提取为函数（数据对象为参数）③ 第一阶段用无中间结构的中间对象传递 ④ 改造 ⑤ 测试 ⑥ 再迭代拆分更多阶段
- 注意：中间数据对象在设计上应该是不可修改的

## Mental Models
- **提炼的反向操作同样常用**：内联的动机是"间接层不值得存在"
- **命名优先于结构**：提炼/改名/参数化这一小套是每天都要用的
- **组合成类 vs 组合成变换**：有状态过程→类；纯数据变换→变换

## Code Examples
```javascript
// 提炼函数（printOwing 案例）：注释 → 函数名
//print details
console.log(`name: ${invoice.customer}`);
// →
function printDetails(outstanding) {
  console.log(`name: ${invoice.customer}`);
  console.log(`amount: ${outstanding}`);
}
```
- **What it demonstrates**: 注释是提炼的向导；嵌套函数可访问外围作用域变量

## Worked Example
改变函数声明的迁移式：`amountFor(aPerformance, play)` 要把 `play` 参数去掉——先在函数体内用 `playFor(aPerformance)` 替换 `play`（编译、测试），再把参数从签名与所有调用点删除（编译、测试），而不是一次性签名+调用点全改。

## Key Takeaways
1. 提炼前先清理局部变量（查询/内联），提炼就会明显变简单
2. 改名：小作用域直接改，大作用域先封装
3. 频繁出现的参数组合→引入参数对象；同一批函数+数据→组合成类/变换
4. 拆分阶段是"多变化方向"的解药——中间结构用不可变数据对象
5. 每个做法都按清单走：编译（或语言检查）→测试→提交
