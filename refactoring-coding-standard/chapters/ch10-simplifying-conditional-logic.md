# 第10章：简化条件逻辑

## Core Idea
条件逻辑组把"不是所有分支都重要"的判断代码改写为清晰形式：分解、合并、卫语句、多态、特例与断言。目标不是消灭条件，而是让条件表达意图。

## Frameworks Introduced

### 分解条件表达式（Decompose Conditional）
- 动机：长条件逻辑 + 长分支体把"做什么"淹没在"怎么做"里
- 做法：① 把条件提为判断函数（`isSummer(date)`）② 把 if/else 分支体提炼为独立函数 ③ 测试
- 收益：阅读者先看到意图，细节退居函数体

### 合并条件表达式（Consolidate Conditional Expression）
- 动机：一串互不相干却共享结果的 if；或嵌套 if 的同合并
- 做法：① 确认条件无副作用 ② 用 && / || 合并 ③ 测试；特别地，把重复条件的 switch 子树视为"合并条件"候选
- 注意：条件语义不同（"同一结果的不同判断来源"）才该合并；顺序敏感的（先判 null）别合并

### 以卫语句取代嵌套条件表达式（Replace Nested Conditional with Guard Clauses）
- 动机：条件嵌套入迷宫；"早返回"使每个分支都直白
- 做法：① 选一个最外层条件，将其语义取反成"早退"卫语句 ② 逐层重复，直到所有分支平铺 ③ 测试
- 决策：**卫语句 vs 主循环结构**——一个分支是主线，一个分支是特例→特例用卫语句；所有分支同等重要→用 if/else 链

### 以多态取代条件表达式（Replace Conditional with Polymorphism）
- 动机：多个 switch 基于同一条件（重复的 switch）；条件分支的"类型"是新加分支时都要改的地方
- 做法：① 把条件提取为类型码/类层次 ② 子类覆写 `amount()` 或 ③ 用表驱动的双分派；逐个分支搬移，测试共存
- 变体：**以多态取代条件逻辑的另一个方向**——"类型码 + 派生类"组合（配合以子类取代类型码）
- 注意：只有一个 switch、条件简单时不做——多态有间接性代价

### 引入特例（Introduce Special Case）
- 动机：大量代码检查 `obj == null` 或 "N/A" 等特殊值；特例角色（空对象/零对象）到处散落
- 做法：① 建特例类（或特例记录、transform 包装）② 覆写需要的行为（通常是返回默认值）③ 把客户端检查改为调用统一接口，或让特例类共享基类/接口 ④ 逐个测
- 反例：**null 判断的数量多不是判据**——先看是否重复"同一默认值形状"的行为（三次法则）；各调用点行为不同（有的报错、有的跳过、有的默认值）或只判一次 → 保持卫语句，不特例化（黑名单）
- 常见目标：空对象（null object）、缺省值对象

### 引入断言（Introduce Assertion）
- 动机：代码依赖某个不变量，但被当作"注释说明"交流，人读时忽略
- 做法：① 找出假设成立才运行正确的代码 ② 在假设处加 assert（生产环境可关）③ 测试
- 要点：断言不做生产逻辑；"断言失败=程序错误"不是 bug 处理机制——只把不变量说清楚

## Mental Models
- **条件逻辑的层次**：一行条件→分解；同结果→合并；异形嵌套→卫语句；类型驱动→多态；空值驱动→特例；不变量→断言
- **主-特分离**：主线+特例用卫语句；多分支平等才 if/else
- **多态是"变化集中"的武器**：新增分支只改一处（新增子类），代价是间接层

## Worked Example
以卫语句取代嵌套条件：
```javascript
// 前
function payAmount(employee) {
  if (employee.isSeparated) { return {amount: 0, reason: "SEP"}; }
  if (employee.isRetired) { return {amount: 0, reason: "RET"}; }
  // 主线计算
  ...
}
// 后（取反为早退）
if (employee.isSeparated) return {amount: 0, reason: "SEP"};
if (employee.isRetired) return {amount: 0, reason: "RET"};
```
回访提示：两条早退都返回同一形状的默认值——这正是引入特例的信号，可进一步用 `Nothing`/`Retired` 特例消除分支。

## Key Takeaways
1. 条件从"长"到"语义化"：分解→合并→卫语句→多态→特例→断言，逐级升档
2. 卫语句的适用判据："是否为特例"
3. 重复的 switch 是多态的唯一正当主角；switch 并非原罪
4. 断言放不变量，不放业务判断；不要为断言写测试
5. 特例与卫语句可接力：先卫语句迫近，再多态/特例消除
