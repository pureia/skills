# 术语表

**被拒绝的遗赠（Refused Bequest）** — 子类继承超类实现但拒绝其接口：继承体系设计错误，轻则忽略，重则改用委托取代（Ch3、Ch12）。

**坏味道（Bad Smell）** — 代码中的可疑信号（24 种），提示需要重构但不直接定义修改（Ch3）。

**基本类型偏执（Primitive Obsession）** — 用整数/字符串代替领域概念（钱、坐标、范围）的坏味道（Ch3）。

**可观察行为（Observable Behavior）** — 重构定义中的不变项：用户关心的行为在重构前后一致；性能、内部调用栈可变化（Ch2）。

**两顶帽子（Two Hats）** — Kent Beck 的比喻：添加功能与重构是两个互不混淆的状态（Ch2）。

**三类变化的坏味道对** — 发散式变化（一模块多变化方向）与霰弹式修改（一变化散布多模块）互为镜像；依恋情结是反模块化（Ch3）。

**中间人（Middle Man）** — 接口一半只做委托转发的类；用移除中间人或内联函数处理（Ch3、Ch7）。

**冗赘的元素（Lazy Element）** — 没有实质贡献的程序元素（函数/类），应内联或折叠（Ch3）。

**夸夸其谈通用性（Speculative Generality）** — 为"总有一天"预置的钩子/参数/抽象（Ch3）。

**临时字段（Temporary Field）** — 仅某种特定情况才设置的字段，应提炼类（Ch3）。

**令修改容易（Making Change Easy）** — Kent Beck：先修改代码让新特性容易加入，再添加新特性（Ch2）。

**内幕交易（Insider Trading）** — 模块间过多私下数据交换，应搬移/隐藏委托（Ch3）。

**纯数据类（Data Class）** — 只有字段与访问函数、行为被置于错误位置的类（Ch3）。

**已发布接口（Published Interface）** — 声明者无权修改客户端代码的接口；迁移式改名（壳+转发）是解法（Ch2）。

**测试驱动开发（TDD）** — 测试→编码→重构短循环，每小时重复多次（Ch4）。

**设计耐久性假说（Design Stamina Hypothesis）** — 改善内部设计可延长软件开发高速期（Ch2）。

**三次法则（Three Strikes Rule）** — 第一次做，第二次反感，第三次重构（Ch2）。

**自测试代码（Self-Testing Code）** — 测试代码随产品代码入库、完全自动化、自我检验、频繁运行（Ch4）。

**命名（Naming）** — 编程中最难的两件事之一；想不出好名字→背后可能有更深的设计问题（Ch3）。

**函数组合成类/变换** — 对一组函数与数据的两条组织路径：类（有状态）或变换（只读数据）（Ch6）。

**命令（Command）** — 把复杂函数包装成对象以分步执行、复用上下文的模式（Ch11）。

**重构（名词）** — 对软件内部结构的一种调整，在不改变可观察行为的前提下提高可理解性、降低修改成本（Ch2）。

**重构（动词）** — 使用一系列重构手法，在不改变可观察行为的前提下调整结构（Ch2）。

**重构名录（Catalog）** — 按"名称/速写/动机/做法/范例"格式记录的重构手法集合（Ch5）。

**数据泥团（Data Clumps）** — 总是成群出现的数据项（字段/参数），应提炼为对象（Ch3）。

**依恋情结（Feature Envy）** — 函数对别模块的数据/行为好感过甚，应搬移函数（Ch3）。

**值对象 vs 引用对象** — 小且无身份用值（整体替换）；大且需身份用引用（仓储共享）（Ch9）。

**重构的节奏** — 小步修改 + 每步编译/测试/提交 = 防止混乱的关键（Ch1）。

**分支合并成本** — 特性分支存活时间越长合并难度指数上升；持续集成是解药（Ch2）。

**卫语句（Guard Clause）** — 特例提前返回，避免嵌套条件（Ch10）。

**消息链（Message Chain）** — 长串取值调用；用隐藏委托关系治理（Ch3）。

**测试覆盖率** — 只能说明哪些代码没被覆盖，不能衡量测试质量（Ch4）。

**测试夹具（Fixture）** — 测试前配置的对象/数据；推荐 beforeEach 重建保证独立性（Ch4）。

**特例（Special Case）** — 空对象/默认值对象简化条件判断（Ch10）。

**数据与行为** — 模块化的原则：最大化区域内交互、最小化跨区域交互；数据与行为一起变化（Ch3）。

**类型码** — 以字符串/数字表达变体；用"以子类取代类型码+多态"消除（Ch12）。

**银钳子** — 重构的定位：不是银弹，但可始终良好地控制代码（Ch2）。

**语义距离** — 函数"做什么"与"如何做"之间的隔阂；是提炼决策的分水岭（Ch3）。
